# 足し算・引き算のセルは、全軸を持つ側のセルからだけ作る

2026-11-02

## 決めたこと

`+` と `-` の連なり(`'A' - ('B' + 'C')` なら項は A、-B、-C)は、括弧と符号反転を外して1つにまとめて扱う。結果のセルは、連なりの全軸を持つ項のセルの和集合にだけ作る。軸の少ない項は、既にあるセルに足し引きするだけで、新しいセルを作らない。項に値がないセルでは 0 として扱う。どの項も全軸を持たないときは、各項を足りない軸の全メンバーに広げて足す。値は左の項から順に足し引きする。

## 理由

軸の少ない側を全メンバーに広げると、疎なメジャーが密になる。1億セル(充填 0.17%)の売上に `'単価'[商品, 期間]` を足すだけで 6×10^10 セルになり、作れない。Essbase も、数式が新しいブロックを作るのは明示したときだけにしている。

連なりにまとめるのは、括弧の付け方で結果のセルが変わらないようにするため。2項ずつ決めると、`('A' + 'B') + 'C'` と `'A' + ('B' + 'C')` で結果が変わる(`'B' + 'C'` が先に全軸のセルを作ってしまう)。

## 選ばなかった案

- **設計書のとおり、空を 0 として全組み合わせに広げる**: 上の理由で、PoC の規模では実現できない。
- **2項ずつ決め、どちらも全軸を持たないときは両側にある組だけをセルにする**(Fable の最初の推奨): 括弧の付け方で結果が変わる。

## 影響

- `'売上' + 1` は売上にあるセルにだけ 1 を足す。
- 設計書の数式言語タブ(「空と0は区別する」の表と方針)を、この決定に合わせた。
- 全軸を持つ項がない式(`'単価'[商品, 期間] + '人員'[部門, 期間]` など)は、足りない軸の全メンバーに広げる。軸の少ない項どうしなので、広げた先は全組み合わせより小さい。利用者の確認はまだ。
- 結果のメジャーの軸が式より多いときに全メンバーへ広げる動き(`SUM('売上')` を期間ごとの結果に置くなど)は、この決定の対象外で、今までどおり。
