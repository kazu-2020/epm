# 足し算・引き算のセルは、全軸を持つ側のセルからだけ作る

2026-11-02、2026-11-03 改訂(結果の形はメジャーの宣言で決める)

## 決めたこと

計算メジャーの結果の形(軸)は、式ではなくメジャーのディメンション宣言で決める。式の各項は宣言の形へブロードキャストする。宣言は利用者が書いたものなので、これは暗黙に軸を増やす操作ではない。保存時の検査は次のとおり。

- **宣言が足りない**(項が宣言にない軸を持つ): エラー。その軸を合計で畳むか平均で畳むかを、エンジンは決められない。メッセージで「`SUM(…, BY …)` で畳むか、宣言に足してください」と直し方を示す。
- **宣言が多すぎる**(どの項にも出てこない軸が宣言にある): 警告にとどめ、計算はする。同じ値がその軸の全メンバーに並ぶだけなので書き間違いのことが多いが、わざと広げる場合もある。
- メジャーを作るときは、式に出てくる軸を宣言の初期値として出す。
- セル数の多さは数式の文法では止めず、1メジャーのセル数の内部上限で止める。

足し算と引き算でどのセルを作るかは、次のとおり。

`+` と `-` だけでつないだ式は、括弧と符号反転を外し、符号付きの項の和として1つにまとめて扱う。項は `+` と `-` 以外でできた部分(メジャー、数値、`'単価' * '数量'`、`SUM(...)` など)で、`'A' - ('B' + 'C')` なら A、-B、-C の3項になる。結果のセルは、式の全軸(項の軸を合わせたもの。宣言の軸ではない)を持つ項のセルの和集合にだけ作る。軸の少ない項は、既にあるセルに足し引きするだけで、新しいセルを作らない。項に値がないセルでは 0 として扱う。どの項も全軸を持たないときは、各項を足りない軸の全メンバーに広げて足す。値は左の項から順に足し引きし、括弧は足す順番にも効かない。`'A' + ('B' + 'C')` の値は `('A' + 'B') + 'C'` と同じ順番で足すので、`0.1 + (0.2 + 0.3)` は 0.6 でなく 0.6000000000000001 になる。

## 理由

宣言で形を決めるのは、広げる先を利用者が書いたものにするため。式だけで決めると、どの項も全軸を持たない式を広げるかどうかは暗黙の規則になり、利用者が予想しにくい。宣言にない軸を持つ項をエラーにし、使われない宣言の軸を警告にすれば、書き間違いはどちらも保存時に見える。全軸を宣言でなく式から数えるのは、宣言だけにある軸(警告を出す軸)のせいで、全軸を持つ疎な項まで密に広げないため。

軸の少ない側を全メンバーに広げると、疎なメジャーが密になる。1億セル(充填 0.17%)の売上に `'単価'[商品, 期間]` を足すだけで 6×10^10 セルになり、作れない。Essbase も、数式が新しいブロックを作るのは明示したときだけにしている。

項の和にまとめるのは、括弧の付け方で結果のセルが変わらないようにするため。2項ずつ決めると、`('A' + 'B') + 'C'` と `'A' + ('B' + 'C')` で結果が変わる(`'B' + 'C'` が先に全軸のセルを作ってしまう)。

## 選ばなかった案

- **設計書のとおり、空を 0 として全組み合わせに広げる**: 上の理由で、PoC の規模では実現できない。
- **結果の形を式から決め、全軸を持つ項がないときは広げない**: 宣言があるのに式の形を優先すると、宣言との食い違いを毎回エラーにするしかなく、`'単価' + '人員'` のような式が書けない。
- **`+` を2項ずつ順に決め、どちらの項も全軸を持たないときは、両方に値がある組み合わせだけをセルにする**(Fable の最初の推奨): `'単価'[商品, 期間] + '人員'[部門, 期間]` なら、同じ期間に単価と人員の両方があるときだけ商品×部門×期間のセルを作り、どちらかしかない期間は空にする。広げる量は減るが、上の理由で括弧の付け方で結果が変わる。

## 影響

- `'売上' + 1` は売上にあるセルにだけ 1 を足す。
- 設計書の数式言語タブ(「空と0は区別する」の表と方針)を、この決定に合わせた。
- 全軸を持つ項がない式(`'単価'[商品, 期間] + '人員'[部門, 期間]` など)は、足りない軸の全メンバーに広げる。結果の形は宣言で決まっているので、2026-11-03 の改訂でこの動きも確定した。商品1,500×部門300×期間36なら約1,600万セルで、ほぼすべて埋まる。
- 結果のメジャーの軸が式より多いとき(`SUM('売上')` を期間ごとの結果に置くなど)は、足りない軸の全メンバーへ広げ、その軸を保存時に警告する。警告に出す軸は `formula::check_axes` の `broadcast` で返す。
- 宣言が足りないときのエラーは `ReducesAxesWithoutAggregation`(式全体)と `AxisNotInResult`(`BY` の軸)で、今の実装のまま。
- 1メジャーのセル数の上限は、値を測ってから決める。まだ実装していない。宣言の初期値を出すのは画面の仕事で、エンジンには入れない。
