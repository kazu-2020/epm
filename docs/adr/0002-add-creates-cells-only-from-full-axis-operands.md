# 足し算・引き算のセルは、全軸を持つ側のセルからだけ作る

2026-11-02

## 決めたこと

`+` と `-` だけでつないだ式は、括弧と符号反転を外し、符号付きの項の和として1つにまとめて扱う。項は `+` と `-` 以外でできた部分(メジャー、数値、`'単価' * '数量'`、`SUM(...)` など)で、`'A' - ('B' + 'C')` なら A、-B、-C の3項になる。結果のセルは、式の全軸を持つ項のセルの和集合にだけ作る。軸の少ない項は、既にあるセルに足し引きするだけで、新しいセルを作らない。項に値がないセルでは 0 として扱う。どの項も全軸を持たないときは、各項を足りない軸の全メンバーに広げて足す。値は左の項から順に足し引きし、括弧は足す順番にも効かない。`'A' + ('B' + 'C')` の値は `('A' + 'B') + 'C'` と同じ順番で足すので、`0.1 + (0.2 + 0.3)` は 0.6 でなく 0.6000000000000001 になる。

## 理由

軸の少ない側を全メンバーに広げると、疎なメジャーが密になる。1億セル(充填 0.17%)の売上に `'単価'[商品, 期間]` を足すだけで 6×10^10 セルになり、作れない。Essbase も、数式が新しいブロックを作るのは明示したときだけにしている。

項の和にまとめるのは、括弧の付け方で結果のセルが変わらないようにするため。2項ずつ決めると、`('A' + 'B') + 'C'` と `'A' + ('B' + 'C')` で結果が変わる(`'B' + 'C'` が先に全軸のセルを作ってしまう)。

## 選ばなかった案

- **設計書のとおり、空を 0 として全組み合わせに広げる**: 上の理由で、PoC の規模では実現できない。
- **`+` を2項ずつ順に決め、どちらの項も全軸を持たないときは、両方に値がある組み合わせだけをセルにする**(Fable の最初の推奨): `'単価'[商品, 期間] + '人員'[部門, 期間]` なら、同じ期間に単価と人員の両方があるときだけ商品×部門×期間のセルを作り、どちらかしかない期間は空にする。広げる量は減るが、上の理由で括弧の付け方で結果が変わる。

## 影響

- `'売上' + 1` は売上にあるセルにだけ 1 を足す。
- 設計書の数式言語タブ(「空と0は区別する」の表と方針)を、この決定に合わせた。
- 全軸を持つ項がない式(`'単価'[商品, 期間] + '人員'[部門, 期間]` など)は、足りない軸の全メンバーに広げる。軸の少ない項どうしなので、広げた先は全組み合わせより小さい。利用者の確認はまだ。
- 結果のメジャーの軸が式より多いときに全メンバーへ広げる動き(`SUM('売上')` を期間ごとの結果に置くなど)は、この決定の対象外で、今までどおり。
