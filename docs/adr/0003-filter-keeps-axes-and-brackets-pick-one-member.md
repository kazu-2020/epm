# 絞り込みは FILTER で軸を残し、角かっこは1メンバーを取り出して軸を消す

2026-11-03

## 決めたこと

メジャーをディメンションのメンバーで絞る書き方は2つある。軸を残すか消すかは、メンバーの数でなく書き方で決まる。

- `FILTER(値, 'D' = 'm')` と `FILTER(値, 'D' IN ('m1', 'm2'))` は、値を D のメンバーに絞る。D の軸は残る。値には式も書ける。
- `'X'['D': 'm']` は、X から D のメンバーを1つ取り出し、D の軸を消す。角かっこはメジャー名(または数値)の直後にだけ書け、メンバーは1つだけ。2つ以上書くと構文エラーになる。

予実差は `'粗利'['バージョン': '実績'] - '粗利'['バージョン': '予算']` と書く。バージョンの軸が消えるので、両方の座標がそろって引ける。

## 理由

設計書の書き方は角かっこ1つで、「1メンバーなら軸を消し、2つ以上なら残す」という規則だった。この規則では、メンバーを1つから2つに増やしただけで結果の軸が変わり、その先の式が壊れる。保存時の軸の検査で止まりはするが、エラーは「軸が余っている」と出て、原因から遠い。書き方で決めれば、角かっこに2つ書いた時点で構文エラーにでき、利用者には FILTER を使うよう案内できる。

一番多い使い方(バージョンを1つに固定する)が一番短く書ける。Pigment と Anaplan も、1メンバーを選ぶ書き方で軸を消す(記憶ベースで、未確認)。

## 選ばなかった案

- **角かっこ1つで、1メンバーなら軸を消す(設計書の書き方)**: 上の理由。
- **常に軸を残す絞り込みと、`SUM(値, WITHOUT 軸)` による軸の削除**: 記法は統一できる。しかし絞り込みを忘れた `SUM('粗利', WITHOUT 'バージョン')` が、実績・予算・見込の合計をエラーなしで出す。BY で既に書けることに、気づきにくい誤りを足すだけになる。
- **軸を消す専用の関数を作り、1メンバーに絞られていなければ保存時エラーにする**: 安全だが、属性で絞った場合などは、1メンバーかどうかを保存時に決められない。

## 影響

- 1つの部門に絞って部門の軸を残したいときは `FILTER('売上', '部門' = '営業1部')` と書く。角かっこを使うと軸が消え、結果のメジャーの軸と合わないので保存時に止まる。この安全は保存時の軸の検査に頼っている。
- 属性での絞り込み(`'部門'.'事業部'` など)は、入れるなら FILTER の条件として足す。
