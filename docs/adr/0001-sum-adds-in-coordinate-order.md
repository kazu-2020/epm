# SUM はグループのセルを座標の小さい順に足す

2026-11-03

## 決めたこと

SUM は、グループに入るセルを座標の小さい順に、1つずつ足す。座標を比べるときの軸の順番は DimensionUlid の小さい順。

## 理由

f64 の足し算は順番で結果の末尾が変わる。順番を決めないと、同じ入力でも実行ごとに値が変わり、評価器と oracle(DuckDB)の結果を完全一致で突き合わせられない。許容付きの比較にすると、合計が 0 か 0 に近い値かで後の割り算が空になるかどうかが変わり、許容では吸収できない。

順番を決めれば、評価器・oracle・これから作る列のエンジンがビット単位で一致し、差分再計算の結果も全体再計算と一致させられる。

## 選ばなかった案

- **許容付きの比較(相対 1e-9)**: 上の割り算の問題で、正しい実装どうしでも落ちる。
- **順番に左右されない正確な累積(固定小数点、superaccumulator)**: SUM の入力の多くは計算メジャーの結果で、10進の入力ではない。速さとメモリの代償に見合わない。

## 影響

- DuckDB では `SUM(value ORDER BY 軸...)` と書く。素の `SUM` は並列に足すので実行ごとに順番が変わる。
- 列のエンジンは、メジャーの軸の並びが DimensionUlid の順と違うとき、SUM の前に並べ替えが要る。メジャーの格納順を DimensionUlid の順に揃えるかは、列のエンジンを作るときに決める。
