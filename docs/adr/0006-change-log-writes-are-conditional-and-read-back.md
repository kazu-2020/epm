# 変更ログの書き込みは条件付きにし、結果が分からなければ読み直す

2026-11-05

## 決めたこと

変更ログを S3 に置く案と PostgreSQL に置く案のどちらでも、担当は次の守りを持つ。どちらの案にするかはまだ決めていない。根拠は `storage/quint/` のモデルで、守りを1つずつ外すと性質が破れることを確かめた(結果は `storage/quint/README.md`)。

- **結果が分からない書き込みは、読み直して判定する。** 応答が来ないとき、成功とみなさない。読み直したマニフェスト(PostgreSQL では先頭の Commit Sequence)が自分の書いた中身と一致すれば成功、書く前のままなら再送、どちらでもなければ読み込み直す。失敗(S3 の 412)も「ほかの担当にフェンスされた」証拠にはしない。自分の再送が先に通った結果でもありうる。
- **重複排除には、確定した変更ログから作った Request ID の集合を使う。** ACK が失われたクライアントの再送は、担当の交代をまたいで届く。新しい担当は読み込みのときに変更ログから集合を作り直す。
- **書き込みは、前に読んだ状態を条件にする。** S3 ではマニフェストをすべて If-Match で書く。PostgreSQL では (ワークスペース, Commit Sequence) の一意制約で、同じ位置に2回入らないようにする。

S3 案では、さらに次の3つを持つ。

- **新しい担当は、受け付けを始める前にマニフェストを1回書く(フェンス)。** これで古い担当の書き込みは必ず 412 になる。
- **読み込んだマニフェストのエポックが自分より新しければ、担当をやめる。**
- **セグメントのキーにエポックを入れ、1つの担当は同じキーに別の中身を書かない。** 再起動した担当は、配置コントローラーから新しいエポックをもらう。

PostgreSQL 案では、さらに次の2つを持つ。

- **変更ログへの追記と、リースのエポックの検査を1つのトランザクションで行う。**
- **書き込みに失敗した古い担当は、リースを読んで止まる。**

## 理由

- 結果が分からない書き込みを成功とみなすと、確定していない変更に ACK を返す。モデルでは両方の案で `refinesChangeLog` が破れた。
- 担当が自分の手元の集合だけで重複を排除すると、交代のあとに同じ Request ID が2回入る。両方の案で `refinesChangeLog` が破れた。
- 条件を外すと、遅れて届いた古い再送が確定済みの変更ログを巻き戻す。PostgreSQL 案でも、リースの検査は書き手を1台に絞るだけで、その1台の古い再送は防げない(固定の手順 `lateResendRollsBackTest` で確かめた)。
- S3 案の変更ログそのものの安全性は、マニフェストの If-Match だけで成り立つ。フェンスとエポックの検査を外しても `refinesChangeLog` は破れなかった。それでもフェンスが要るのは、外すと新しい担当が受け付けを始めたあとも古い担当がコミットと ACK を続け、新しい担当がそのコミットを見ないまま読ませるからである(`newestOwnerSeesAcknowledged`)。エポックの検査を外すと、古い担当が新しいエポックのあとに確定できる(`staleEpochNeverCommits`)。
- セグメントのキーが Commit Sequence だけだと、交代を知らない古い担当が確定済みのセグメントを同じキーで上書きできる。マニフェストは変わらないまま、確定した中身が変わる。
- PostgreSQL 案では、リースの検査がフェンスとセグメントのキーの役をする。配置コントローラーがリースを書いた時点で、古い担当のコミットは失敗する。フェンスを書く処理も、孤児のセグメントもない。古い担当がリースを読まないと、読み直しと再送をいつまでも繰り返す。

## 選ばなかった案

- **S3 のセグメントも `If-None-Match: *` で書く**: 同じ担当が同じキーに別の中身を書かないことは、上の約束で守る。モデルでは約束が守られる限り要らなかった(`segmentsNeverChange`)。ただしモデルのセグメントの PUT は1回で届き、遅れて届く PUT や再送の PUT はない。実装で約束が破れたことに気づく手段として、あとで足してもよい。
- **412 を受けたらフェンスされたとして止まる**: 自分の再送が先に通った 412 で、確定した変更を捨てて止まってしまう。

## 影響

- 交代を知らない古い担当は、手元の状態から古い値を読ませうる。これはストアのフェンスでは防げない。読み取りはまだモデルにないので、防ぐ仕組み(リースの期限など)はスナップショットと一緒に決める。
- 読み込み直すときは、まだ ACK していない batch を捨て、クライアントの再送に任せる。
