# 変更ログの書き込みは条件付きにし、結果が分からなければ読み直す

2026-11-05

## 決めたこと

変更ログは S3 に置く。担当はセグメントを `{ワークスペース}/log/{位置}` に If-None-Match で PUT し、200 なら ACK する。担当は次の守りを持つ。根拠は `storage/quint/seqlog.qnt` のモデルで、守りを1つずつ外すと性質が破れることを確かめた(結果は `storage/quint/README.md`)。Rust の実装 `storage/change_log/` でも、同じ変異をシミュレーションが捕まえる。

- **すべての書き込みを If-None-Match にする。** 1つの位置には1回しか入らない。
- **結果が分からない書き込みは、読み直して判定する。** 応答が来ないとき、409 のとき、412 のときに、その位置を読む。空なら同じ中身で再送する。自分のエポックで同じ中身なら成功とみなす。自分より新しいエポックなら止まる。412 を「ほかの担当に取られた」証拠にはしない。自分の再送が先に通った結果でもありうる。
- **自分のエポックで別の中身を見たら、alarm を出して止まる。** 1つのエポックは1つの位置に1つの中身しか書かないので、起きれば前提が破れている。
- **重複排除には、確定した変更ログの Request ID と、PUT 中の Request ID の和を使う。** ACK が失われたクライアントの再送は、担当の交代をまたいで届く。新しい担当は読み込みのときに変更ログから集合を作り直す。
- **新しい担当は、受け付けを始める前に次の位置に空のセグメントを置く(フェンス)。** フェンスの位置が古いエポックに取られていたら、その中身を自分の view と重複排除の集合に足してから、次の位置でやり直す。データの書き込みで古いエポックを見たら、alarm を出して止まる。
- **読み込んだ末尾の位置のエポックが自分と同じか新しければ、担当をやめる。**
- **1つの担当が同時に送る PUT は1つにする。**
- **再起動した担当も、読み込み直す担当も、配置コントローラーから新しいエポックをもらう。**

## 理由

- 結果が分からない書き込みを成功とみなすと、確定していない変更に ACK を返す(`refinesChangeLog`)。
- If-None-Match を外すと、遅れて届いた古い PUT が確定済みの位置を上書きする(`refinesChangeLog`、`segmentsNeverChange`)。
- 担当が手元の集合だけで重複を排除すると、交代のあとに同じ Request ID が2回入る。PUT 中の Request ID を入れないと、flush で batch を空にしたあとに同じ Request ID が次の位置にもう1回入る(どちらも `refinesChangeLog`)。
- フェンスを外してもログは壊れない。それでも要るのは、外すと新しい担当が受け付けを始めたあとも古い担当がコミットと ACK を続け、新しい担当がそのコミットを見ないまま読ませるからである(`newestOwnerSeesAcknowledged`)。
- 末尾のエポックの検査を外すと、古い担当が新しいエポックのあとに確定できる(`staleEpochNeverCommits`)。
- PUT を同時に2つ送ると、位置 N+1 が N より先に入り、N が空いたまま N+1 の batch を ACK する(`refinesChangeLog`、`slotsContiguous`)。
- 読み込み直すときに同じエポックを使うと、前の PUT が遅れて届いたとき、自分のエポックの位置に知らないコミットが入る。新しいエポックをもらえば、その位置は古いエポックとして扱われ、中身を view に足す経路に入る。

## 選ばなかった案

- **412 を受けたら止まる**: ログは壊れないが、自分の再送が先に通った 412 で、確定した変更を ACK しないまま止まる。SDK や `object_store` crate が 5xx のあとに自動で再送するので、よく起きる。
- **変更ログを PostgreSQL に置く**: 東京の S3 の PUT の p99 は 85〜91ms で、戻す条件の 500ms を下回った。

## 影響

- 交代を知らない古い担当は、手元の状態から古い値を読ませうる。これはストアのフェンスでは防げない。読み取りはまだモデルにないので、防ぐ仕組み(リースの期限など)はスナップショットと一緒に決める。
- 読み込み直すときは、まだ ACK していない batch を捨て、クライアントの再送に任せる。
